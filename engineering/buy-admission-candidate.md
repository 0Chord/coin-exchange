# BUY 주문 후보 계산 · #83

이 계산기는 ‘이 주문을 접수한다면 어떤 돈과 기록이 필요한가’를 돌려준다. 실제 접수나 저장을 수행하지 않는다. 합의한 상세 계약은 [이슈 #83](https://github.com/0Chord/coin-exchange/issues/83)에 있다.

## 먼저 볼 세 가지

| 가진 돈과 주문 | 계산 결과 | 원래 잔고 |
| --- | --- | --- |
| 1,000, 가격 100 × 3개, 수수료 없음 | 사용 가능 700 / 예약 300 후보 | 1,000 / 0 그대로 |
| 위 주문, 최대 수수료율 0.2% | 수수료 준비 0.6을 더해 699.4 / 300.6 후보 | 1,000 / 0 그대로 |
| 가진 돈 200, 필요한 돈 300 | 자산·현재 200·필요 300·부족 100을 담은 거절 | 200 / 0 그대로 |

수수료 준비액은 아직 청구한 수수료가 아니다. `Calculated`는 계산 완료이며, 주문 접수 성공을 의미하지 않는다.

## 입력에서 결과까지

1. 호출자가 주문 원본, 마켓, 확정된 수수료 정책, 현재 잔고, 기록 ID와 시각을 넘긴다.
2. 계산기가 주문의 지원 조건과 식별자 표현을 확인한다. 다른 사용자의 잔고나 잘못된 서버 정책을 연결했다면 예외로 중단한다.
3. 기존 주문 계산기가 대금과 최대 수수료 예약액을 계산한다. 공식을 다시 만들지 않는다.
4. 기존 잔고 객체에 예약을 요청해 새 잔고를 받는다. 부족하면 명시적인 거절이다. 원본 객체는 바뀌지 않는다.
5. 신규 ACTIVE 예약과 RESERVE 두 항목을 만들고 서로의 사용자·자산·금액을 확인한 뒤 후보로 돌려준다.

필요액을 표현할 수 없는 경우는 거절이다. 유효한 필요액을 기존 hold에 더하다 범위를 넘는 경우는 처리 오류다. 전체 계산을 넓은 예외 처리로 감싸 둘을 섞지 않는다.

## 코드 읽기 순서

- `OrderAdmissionInput.kt`: 어떤 주문을 계산할지 받는 값.
- `OrderAdmissionCalculator.kt`: 입력 확인 → 기존 규칙 호출 → 결과 조합.
- `OrderAdmissionCandidate.kt`: 주문·새 잔고·예약·원장의 연결을 보존하는 불변 묶음.
- `OrderAdmissionResult.kt`: 계산 후보 또는 예상 거절. 내부 오류는 이 결과로 숨기지 않는다.

모두 `domain-trading/src/main/kotlin/com/exchange/core/trading`에 있다. 새 모듈은 common·fee·order·ledger만 사용한다. 다른 구조 검사 파일의 변경은 이 모듈을 기존 검사 범위에 포함하는 작업이다.
